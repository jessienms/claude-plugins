# todo — 프로젝트 로컬 할 일 목록 스킬 (Codex판)

프로젝트에 붙어 있는, 세션이 끝나도 남는 할 일 목록을 관리한다.

> 아래 명령 예시의 `<skill-dir>` 은 이 SKILL.md 가 있는 폴더(플러그인 설치 경로)를 뜻한다.
> 실행 시 실제 절대 경로로 치환해서 호출한다.

> **데이터 폴더 이름이 `.claude/` 인 이유**: 같은 프로젝트를 Claude Code 와 Codex 양쪽에서
> 쓸 때 할 일 목록이 두 벌로 갈라지지 않도록 **동일한 데이터 폴더를 공유**한다. Codex 전용
> 프로젝트라도 경로는 그대로 `.claude/todo/` 다(이름만 그럴 뿐 Codex 에서 정상 동작한다).

## 왜 스크립트로만 다루는가

할 일 목록은 시간이 지나면 커진다. 항목 하나를 완료 처리하려고 `todo.md` 를 통째로
읽으면 지금 작업과 무관한 수십 개 항목의 상세 내용까지 전부 컨텍스트에 올라온다.

그래서 이 스킬의 모든 동작은 `scripts/todo.sh` 를 거친다. `list` 는 제목만, `show` 는
지정한 항목만 출력하고, `done` 은 해당 블록만 잘라내 백업으로 옮긴다. **`todo.md` 를
`cat`·에디터·파일 읽기 도구로 직접 열지 않는다** — 사용자가 명시적으로 "파일 원본을
보여줘" 라고 할 때만 예외다.

Codex 의 **계획(plan) 도구**와 혼동하지 않는 것도 중요하다. 계획 도구는 지금 이 세션에서
처리 중인 작업의 진행 상황을 추적하는 것이고, 이 스킬은 **세션이 끝난 뒤에도 남아야 하는**
할 일을 파일로 적어 두는 것이다. 사용자가 "todo에 추가해둬", "나중에 할 일로 적어놔"
라고 하면 후자다.

## 파일 레이아웃

```
<프로젝트 루트>/.claude/todo/
├── todo.md                      진행 중인 항목만 (체크리스트)
├── .seq                         ID 카운터 (스크립트가 관리)
└── backup/
    ├── T1-로그인-실패-시-재시도-로직.md
    └── T3-README-오탈자-수정.md    항목당 파일 하나
```

`todo.md` 형식 — 항목 한 줄 + 2칸 들여쓴 상세 줄들:

```markdown
- [ ] (T7) 로그인 실패 시 재시도 로직 <!-- added:2026-07-31 -->
  - 401 이면 토큰 갱신 후 1회 재시도
  - 3회 실패 시 로그아웃
```

ID(`T7`)는 한 번 발급되면 바뀌지 않고 재사용되지도 않는다. 항목이 제거돼도 다른 항목의
ID 는 그대로이므로, 이전 대화에서 언급한 ID 가 나중에 엉뚱한 항목을 가리키는 일이 없다.

## 스크립트

```bash
bash "<skill-dir>/scripts/todo.sh" <서브커맨드> [인자...]
```

리포지터리 안 아무 데서나 실행하면 된다 (git 루트를 찾아 `.claude/todo/` 를 쓴다).
git 저장소가 아니면 **현재 작업 폴더** 기준이다. Codex 는 보통 프로젝트 루트에서
실행되므로 그 폴백이 곧 프로젝트 루트지만, **하위 폴더에서 실행 중이고 git 저장소도
아니라면 `--dir <프로젝트루트>/.claude/todo` 로 명시한다.** 그러지 않으면 이미 적어 둔
항목이 있는데도 "할 일이 없습니다" 로 보이는 혼란이 생긴다.

| 서브커맨드 | 하는 일 |
|---|---|
| `init` | `.claude/todo/` 와 `todo.md` 생성 (이미 있으면 그대로) |
| `add --title "제목" [--body "상세"]` | 항목 추가, 새 ID 출력. `--body -` 면 상세를 stdin 에서 읽음 |
| `list` | ID + 제목만 나열 |
| `show <ID>...` | 지정 항목의 제목·상세 출력 |
| `find <검색어>` | 제목에 검색어가 든 항목의 ID/제목 출력 (없으면 종료 코드 1) |
| `done <ID>... [--note "메모"]` | 완료 처리: 목록에서 빼고 `backup/` 에 보관 |
| `cancel <ID>... [--note "메모"]` | 취소 처리: 동일하되 `status: cancelled` 로 보관 |
| `log` | `backup/` 에 보관된 파일명 나열 |
| `path` | todo.md / backup 경로 출력 |

ID 는 `T7` 도 `7` 도 받는다.

> **Windows**: 스크립트는 bash 스크립트다. Codex 가 PowerShell 로 명령을 실행하더라도
> `bash "<skill-dir>/scripts/todo.sh" ...` 형태로 호출하면 Git for Windows 의 bash 가
> 처리한다. `bash` 가 PATH 에 없으면 사용자에게 Git for Windows 설치를 안내한다.

## 항목 추가

사용자가 "이거 todo에 추가해줘", "방금 얘기한 거 할 일로 적어둬" 라고 하면:

```bash
bash "<skill-dir>/scripts/todo.sh" add --title "로그인 실패 시 재시도 로직" --body "- 401 이면 토큰 갱신 후 1회 재시도
- 3회 실패 시 로그아웃"
```

**제목**은 목록에서 한눈에 알아볼 수 있는 한 줄 요약으로 쓴다. `list` 는 제목만 보여주기
때문에, 제목만 읽고도 무슨 일인지 떠오르지 않으면 목록으로서 쓸모가 없다. "버그 수정"
같은 제목 대신 "로그인 실패 시 재시도 로직" 처럼 대상이 드러나게 쓴다.

**상세**에는 며칠 뒤에 이 항목만 열어 보고 작업을 시작할 수 있을 만큼을 담는다 — 관련
파일 경로, 대화에서 이미 내린 결정, 재현 방법, 제약. 반대로 지금 대화의 잡담까지 옮겨
적을 필요는 없다. 상세가 필요 없는 짧은 일이면 `--title` 만 줘도 된다.

"방금 내용을 추가해줘" 처럼 대상이 대화 맥락에 있으면, 그 맥락을 직접 요약해 제목과
상세를 만든다. 사용자에게 제목을 되묻지 말고, 만든 뒤에 무엇으로 적었는지 보여 준다.

상세가 길거나 따옴표·백틱이 섞여 인용이 지저분해지면 stdin 을 쓴다:

```bash
bash "<skill-dir>/scripts/todo.sh" add --title "결제 모듈 리팩터링" --body - <<'EOF'
- PaymentService 를 인터페이스로 분리 (Services/PaymentService.cs)
- 테스트 더블 추가해서 결제 실패 경로 커버
EOF
```

추가 후에는 발급된 ID 와 제목을 사용자에게 한 줄로 알려 준다.

## 목록 보기

```bash
bash "<skill-dir>/scripts/todo.sh" list
```

출력이 이미 "ID + 제목" 한 줄씩이므로 그대로 보여주면 된다. 상세까지 펼쳐 나열하면
읽기 힘들어지므로, 사용자가 특정 항목을 짚어 물을 때만 `show` 로 펼친다.

```bash
bash "<skill-dir>/scripts/todo.sh" show T7
```

## 완료 / 취소 처리

사용자가 "그거 완료 처리해줘", "todo에서 빼줘" 라고 할 때:

1. 어떤 항목인지 확정한다. ID 를 말했으면 그대로 쓰고, "로그인 재시도 그거" 처럼
   제목으로 말하면 `find` 로 찾는다.
   ```bash
   bash "<skill-dir>/scripts/todo.sh" find "로그인"
   ```
2. 후보가 여럿이거나 확신이 서지 않으면 **후보 목록을 보여주고 턴을 끝내 사용자에게
   어느 것인지 확인받는다.** Codex 에는 선택지 UI 도구가 없으므로, 후보를 나열한 뒤
   같은 턴에 이어서 `done` 을 실행하지 않는다. `done` 은 항목을 목록에서 빼는 동작이라
   엉뚱한 항목을 지우면 사용자는 그 사실을 눈치채기 어렵다. 반면 백업은 남으므로
   되돌릴 수는 있다.
3. 실행한다. 방금 그 작업을 실제로 처리했다면 `--note` 로 어떻게 처리했는지 남긴다 —
   나중에 백업 파일만 봐도 결론을 알 수 있게.
   ```bash
   bash "<skill-dir>/scripts/todo.sh" done T7 --note "AuthClient.RefreshAsync 로 갱신 후 재시도하도록 구현, 커밋 a1b2c3d"
   ```

여러 개를 한 번에 처리하려면 ID 를 나열한다: `done T7 T9 T12`.

하기로 했다가 접은 일은 `cancel` 을 쓴다. 동작은 같고 백업에 `status: cancelled` 로
기록되므로, 나중에 "이건 왜 안 했지" 를 구분할 수 있다.

작업을 끝낸 직후라면 관련 항목이 목록에 있는지 먼저 확인해 보고, 있으면 사용자에게
완료 처리할지 물어보는 것이 자연스럽다. 다만 묻지도 않고 마음대로 지우지는 않는다.
Codex 의 승인 정책이 자동 실행(full-auto 등)으로 설정돼 있어도 마찬가지다 — 쉘 명령이
자동 승인된다는 것은 "이 항목을 지워도 좋다"는 뜻이 아니다.

## 백업 파일

`backup/` 의 파일은 항목당 하나이고, 프론트매터에 `id`/`title`/`status`/`added`/`closed`
가 들어 있다. 목록을 볼 때는 `log` 로 파일명만 훑고, 특정 항목의 내용이 필요할 때만 그
파일 하나를 읽는다. `backup/` 전체를 grep 하거나 여러 파일을 한꺼번에 읽는 것은,
이 구조가 막으려던 바로 그 컨텍스트 낭비다.

## 가드레일

- **`todo.md` 를 직접 편집하지 않는다.** 손으로 고치면 ID 카운터(`.seq`)와 어긋나고,
  전문을 읽게 되어 스킬의 목적이 사라진다. 스크립트에 없는 조작(제목 수정 등)이
  필요하면 사용자에게 어떻게 처리할지 확인한다.
- **항목을 지울 때는 백업을 남긴다.** `done`/`cancel` 은 항상 백업을 만든다. 백업 없이
  버리는 경로는 일부러 만들지 않았다.
- **`.claude/todo/` 를 커밋할지는 사용자가 정한다.** 팀과 공유하려면 커밋하고, 개인
  메모라면 `.gitignore` 에 넣는다. 먼저 물어보고, 시키지 않았으면 건드리지 않는다.
- **`init` 은 필요할 때만.** `add` 가 알아서 디렉터리와 파일을 만들므로, 사용자가
  "todo 셋업해줘" 라고 명시할 때 외에는 굳이 부를 필요가 없다.

## 예시

**사용자:** "방금 얘기한 재시도 로직, todo에 추가해줘."
→ 대화 맥락을 요약해 `add --title "로그인 실패 시 재시도 로직" --body "..."` →
"T7 로 추가했어" 라고 알려 준다.

**사용자:** "지금 할 일 뭐 남았어?"
→ `list` 출력을 그대로 보여준다.

**사용자:** "아까 그 재시도 로직 작업 끝났어. 할일 목록에서 완료로 해줘."
→ `find "재시도"` → T7 확정 → `done T7 --note "..."` → 백업 경로와 함께 보고.
